# CueDeck Review — Latency, Cost, and Code Quality

Reviewed: 2026-09-01
Scope: the whole app, with the same tech stack (Electron + Vite + React, Transformers.js for
local speech-to-text, Ollama / free-tier cloud adapters for responses). Focus on end-to-end
latency and on cost — both cloud free-tier quota and local CPU/memory. Findings that were
already implemented on 2026-08-20 (`docs/LATENCY_AND_QUALITY_REVIEW.md`) are not repeated.

Verification: `npm run check` (Prettier, ESLint, strict `tsc`, 368 unit + integration tests)
and the Playwright E2E suite pass after these changes.

## Part 1 — Latency

### Where a turn's time goes now

Pipeline before this review: endpointer waits `trailingSilenceMs` → encode → IPC → validate →
**STT over the whole clip** → prompt → LLM (prompt eval + first token). After:

```
speech ends
  │ 0.7 s   snapshot + speculative STT starts ──────────────┐
  │ 1.6 s   endpointer fires; encode; IPC; validate          │ overlapped
  ▼         reuse transcript (await if still running) ◄─────┘
            LLM: prompt cache already holds system+profile → first token
```

Approximate budget for a 15-second question, steady state, default preset:

| Stage                                   | Local (Whisper Base + Ollama 7B, CPU)                 | Cloud (Groq Whisper turbo + Cerebras 70B)       |
| --------------------------------------- | ----------------------------------------------------- | ----------------------------------------------- |
| Trailing-silence wait                   | 1.6 s, of which ~0.9 s now overlaps STT               | 1.6 s, of which ~0.9 s overlaps STT             |
| Transcribe on the critical path         | was ~2–8 s → now ~1–7 s (head start)                  | was ~0.5–1.5 s → now often **0** (already done) |
| LLM prompt eval + first token           | was ~1–4 s cold prefix → now ~0.3–1 s (prefix cached) | ~0.2–0.6 s                                      |
| **First words after the speaker stops** | **was ~4–11 s → ~2.5–8 s**                            | **was ~2.5–4 s → ~1.8–2.5 s**                   |

The numbers are estimates from the stage costs measured in the previous review; the app's
status rail reports the real split per turn (and now says "transcribed during the pause" when
the speculative transcript was used).

### L1. Speculative transcription (implemented)

Design constraints that shaped it:

- **Correctness.** A speculative transcript is reused only when the final clip is the snapshot
  plus silence: same session, `frames ≥ snapshot frames`, and no 30 ms window in the tail
  reaches the speech threshold (`hasSound`). Anything else runs a normal pass. The transcript
  can therefore never be of a _different_ clip than the one shown as "Heard".
- **Never a user-visible failure.** Speculation emits no events and its errors are swallowed;
  a failed speculation falls back to a normal pass, which reports real errors.
- **Cost bounds.** Cloud: at most one request in flight per session; a newer snapshot aborts
  the older request. Local: an inference cannot be interrupted without killing the utility
  process (and reloading the model on the next turn), so a stale local job runs to completion
  and the newest snapshot waits behind it — one in flight, one pending, older pendings dropped.
  Explicit Cancel aborts everything, matching existing cancel semantics.
- **Snapshot cost.** `recorder.snapshot()` re-encodes the whole clip on the renderer thread
  (~10–30 ms for a 60 s clip). Chunks are consolidated after each merge so repeated snapshots
  do not re-copy thousands of 128-frame arrays.

Not done (next step if latency needs another step change): incremental transcription during
recording with a live "heard so far" preview. That is a larger change to the worker protocol
and needs stitching logic; the speculative path above captures most of the win for typical
interview questions, where the final pause is the only long one.

### L2. Ollama warmup was causing a reload (fixed)

Ollama's scheduler compares the resident runner's options (`num_ctx`, `num_batch`, GPU layers,
threads…) with each request's and reloads the model on any difference. The warmup sent no
options; `generate` sent `num_ctx: 8192`. Every first turn therefore paid: warmup load →
reload with the new context → prompt eval. `runnerOptions()` is now the single source for
both, and an integration test asserts warmup and generate request the same `num_ctx`.

### L3. Prefix warmup (implemented)

`buildPromptPrefix()` returns the system prompt and the profile/role blocks — exactly the
leading part of `buildPrompt()` for the same inputs (pinned by a unit test). The coordinator
sends it at capture-arm, at app start, and again at submit (using the real per-session mode and
target). Identical warmups that are still in flight are joined, so a slow CPU prefix evaluation
is never queued twice ahead of the real request. Cloud adapters ignore the prefix and keep their
cheap connection warmup.

### L4. Pause length (implemented)

`trailingSilenceMs` (500–5000 ms, default 1600) is a public setting; the coach window offers
three presets. The speculative threshold is capped at `trailingSilenceMs − 300 ms` so even the
quick preset keeps a head start. Old settings files pick up the default through the existing
merge-with-defaults migration; no schema version bump was needed.

### L5. Still open

- Incremental transcription + live preview (above).
- FLAC upload for Groq (halves upload bytes losslessly; `groqWhisper.ts` already accepts the
  MIME type — an encoder in the renderer is the missing piece).
- Adaptive noise floor for the endpointer (fixed RMS thresholds are tied to system volume).
- Previous-exchange context for follow-up questions (quality, not latency).

## Part 3 — Code review notes

Things that were right and are kept: sandboxed renderer with a fixed preload API, Zod on every
IPC payload, sender checks, abort plumbing through every stage, fenced untrusted prompt blocks,
monotonic delta sequencing, and the test tiering. The pipeline was already well-instrumented,
which is what made the timing analysis possible.

Small fixes made in passing:

- `ollama.ts` had an empty `if` on the loopback check — removed.
- `models:cancelDownload` parsed its payload by hand — now `modelsCancelDownloadSchema`.
- `coordinator.generate()` read the profile from disk after transcription (on the critical
  path); it is now read once before STT and reused.
- `session:submit` and `session:speculate` share `wavBytes()` for payload bounds.
- `coachReducer`'s `edit-transcript` branch had a redundant nested condition.

Things reviewed and deliberately left alone:

- `return_timestamps: true` in the Whisper worker: the segments are unused, and dropping
  timestamps might speed decoding slightly, but Transformers.js's chunked long-form path
  depends on them and there is no local model on this machine to measure the change. Left as
  is; worth a benchmark on a machine with a model installed.
- The box-average resampler: adequate for speech; a sinc kernel would not change latency.
- Prompt size: ~350 tokens of system prompt per request is fine for every provider here.

## Addendum (same day) — realism and reliability for mock interviews

Direction: "cheap but reliable, for realistic simulations of interviews". Three additions, all
free-tier friendly and all explicit (nothing switches providers or adds context silently):

| Change                                                                                                                                                                                                             | Cost                               | Why it matters                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Conversation memory** — the last two question/answer pairs travel with each request in a fenced `<previous_exchanges>` block; "Try again" replaces rather than duplicates; Clear forgets; toggle in Preferences. | A few hundred tokens per response. | Follow-up questions ("and how would you scale that?") were answered blind. This was the biggest realism gap left from the previous review (Q7).            |
| **Interviewer follow-up** — one button generates the next interviewer question from the conversation so far and drops it into the transcript box.                                                                  | One ~150-token request.            | Turns the practice deck into a multi-turn mock interview: draw → answer aloud → compare → follow-up → …                                                    |
| **Backup response model** — a user-chosen second provider/model used only when the primary fails before its first token; the status rail says when it answered.                                                    | Zero unless the primary fails.     | Free tiers rate-limit and have outages; per-provider limits rarely coincide, so Groq ⇄ Cerebras as primary/backup is close to always-available at no cost. |

Reliability details: the backup is never used after the primary has started answering (a
second, different answer under the first would be worse than an error), never for a cancelled
session, and the primary's first-token patience drops to 20 s when a backup exists so an outage
costs seconds, not a minute. The README now carries a recommended cheap-and-reliable
configuration (Groq Whisper + Groq/Cerebras 70B, the other as backup, local as offline fallback).

Tests: `test/integration/conversation.test.ts` (memory order and caps, replace-on-regenerate,
clear, off switch, follow-up event and prompt, backup used / not used after first token / not
configured / both fail / cancelled), plus reducer and prompt unit tests. Gate: 393 unit +
integration tests and the 14 E2E tests pass.
